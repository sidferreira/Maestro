# VPN Network Monitoring User Guide

## Overview

Maestro's VPN Network Monitoring feature allows you to capture and analyze all network traffic generated by your app during test execution, without requiring any modifications to the app under test.

## Features

- **Zero app modifications**: No need to instrument, rebuild, or configure your app
- **Comprehensive capture**: Monitor HTTP, HTTPS, WebSocket, and other protocols
- **Detailed metrics**: View request/response details, timing, data transfer sizes
- **Visual reports**: Network data is automatically included in HTML test reports
- **Domain filtering**: Focus on specific domains or exclude third-party traffic

## Requirements

### iOS
- macOS with Xcode installed
- iOS Simulator (iOS 14+) or physical device
- For HTTPS inspection: Trusted CA certificate installed on device/simulator

### Android
- Android SDK installed
- Android Emulator (API 24+) or physical device
- ADB access to the device
- For HTTPS inspection: Custom CA certificate installed in system trust store

## Quick Start

### 1. Enable Network Monitoring

Add the `--enable-network-monitoring` flag to your Maestro test command:

```bash
maestro test --enable-network-monitoring my-flow.yaml
```

### 2. View Network Data in Reports

After test execution, open the generated HTML report. Each flow will include a "Network Monitoring Data" section showing:

- Request/response counts and success rates
- Data transfer sizes (bytes sent/received)
- Average response time
- List of contacted domains
- Detailed request table with URLs, methods, status codes, and timing

### 3. Configure Monitoring (Optional)

Create a network monitoring configuration file `network-config.yaml`:

```yaml
# Enable/disable monitoring
enabled: true

# Capture HTTPS traffic (requires certificate installation)
captureHttps: false

# Maximum body size to capture (in bytes)
maxBodySize: 1048576  # 1MB

# Include only these domains (empty = all domains)
includedDomains:
  - api.myapp.com
  - cdn.myapp.com

# Exclude these domains
excludedDomains:
  - analytics.google.com
  - firebase.google.com

# Capture request/response headers
captureHeaders: true

# Capture request/response bodies (warning: may increase storage)
captureBody: false
```

Use the configuration file:

```bash
maestro test --enable-network-monitoring --network-config=network-config.yaml my-flow.yaml
```

## HTTPS Inspection

### Why HTTPS Inspection?

By default, HTTPS traffic is encrypted end-to-end, so the VPN can only see:
- Destination IP and port
- Amount of data transferred
- Timing information

With HTTPS inspection (MITM - Man-in-the-Middle), you can additionally see:
- Full URL and query parameters
- Request/response headers
- Request/response bodies

### Limitations

**Certificate Pinning**: Apps that implement certificate pinning will reject the custom CA certificate and may:
- Refuse to make network requests
- Display SSL errors
- Function with reduced capabilities

For apps with certificate pinning, you can still monitor:
- Network traffic without decryption
- Connection metadata (domains, timing, data sizes)

### iOS HTTPS Setup

1. **Generate CA Certificate** (automatically done by Maestro on first use)

2. **Install Certificate on Simulator**:
   ```bash
   maestro install-ca-cert --device-id <simulator-udid>
   ```

3. **Trust Certificate**:
   - Open Settings > General > About > Certificate Trust Settings
   - Enable the Maestro CA certificate

4. **Run Tests with HTTPS**:
   ```bash
   maestro test --enable-network-monitoring --capture-https my-flow.yaml
   ```

### Android HTTPS Setup

1. **Generate CA Certificate** (automatically done by Maestro on first use)

2. **Install Certificate on Emulator**:
   ```bash
   maestro install-ca-cert --device-id <emulator-id>
   ```

3. **For API 24+**: Certificate is installed in user trust store by default
   
4. **For System-Level Trust** (required for some apps):
   ```bash
   maestro install-ca-cert --system --device-id <emulator-id>
   ```
   Note: Requires root access (emulator only)

5. **Run Tests with HTTPS**:
   ```bash
   maestro test --enable-network-monitoring --capture-https my-flow.yaml
   ```

## Understanding the Report

### Network Metrics Card

Shows high-level statistics:
- **Total Requests**: Number of HTTP requests made
- **Successful**: Requests with 2xx status codes
- **Failed**: Requests with 4xx/5xx status codes
- **Avg Duration**: Average request response time in milliseconds
- **Bytes Sent**: Total data uploaded
- **Bytes Received**: Total data downloaded
- **Unique Domains**: Number of different domains contacted

### Domains

A list of all domains the app communicated with during the test. Useful for:
- Identifying third-party services
- Detecting unexpected network calls
- Verifying API endpoints

### Network Requests Table

Detailed list of individual requests showing:
- **Method**: HTTP method (GET, POST, etc.)
- **URL**: Full request URL
- **Status**: HTTP status code (color-coded: green for success, red for errors)
- **Duration**: Time taken for the request in milliseconds
- **Size**: Response size in bytes

Note: Only the first 20 requests are shown in the table to keep the report readable. View the full log file for complete details.

## Best Practices

### 1. Filter Unnecessary Domains

Exclude analytics and tracking services to focus on app-specific traffic:

```yaml
excludedDomains:
  - analytics.google.com
  - firebase.google.com
  - facebook.com
  - doubleclick.net
```

### 2. Test Without HTTPS First

Start with basic HTTP monitoring to ensure the VPN setup works correctly, then enable HTTPS inspection if needed.

### 3. Monitor Performance Impact

Network monitoring adds ~5-15% overhead. For performance-sensitive tests, consider:
- Disabling body capture
- Filtering to specific domains
- Running network monitoring on separate test runs

### 4. Review Failed Requests

Check the failed requests section to identify:
- Backend errors
- Network issues
- Invalid API calls
- Authentication problems

### 5. Compare Across Runs

Track network metrics over time to detect:
- Performance regressions
- Unexpected new API calls
- Increases in data usage

## Troubleshooting

### VPN Connection Fails

**Symptoms**: Test fails with "Failed to establish VPN connection"

**Solutions**:
- Ensure ADB is connected (Android) or device is available (iOS)
- Check if another VPN is already active
- Restart the device/emulator
- Check logs: `~/.maestro/logs/network-monitor.log`

### No Network Data Captured

**Symptoms**: Report shows "Network monitoring enabled" but no requests

**Solutions**:
- Verify the app actually makes network requests
- Check domain filters aren't too restrictive
- Ensure VPN is established: `maestro diagnose network`
- Check if app detects VPN and disables networking

### HTTPS Decryption Not Working

**Symptoms**: HTTPS requests show as encrypted or with errors

**Solutions**:
- Verify CA certificate is installed and trusted
- Check if app uses certificate pinning
- Review certificate installation: `maestro list-ca-certs`
- Try with a known app without pinning first

### High Memory Usage

**Symptoms**: Test fails with OOM error when network monitoring is enabled

**Solutions**:
- Disable body capture: `captureBody: false`
- Reduce max body size: `maxBodySize: 102400  # 100KB`
- Add domain filters to reduce captured traffic
- Increase test runner memory: `MAESTRO_JAVA_OPTS=-Xmx2g`

### App Detects VPN

**Symptoms**: App behaves differently or shows errors when monitoring is enabled

**Solutions**:
- Some apps detect VPN presence for security reasons
- This is a limitation of the non-intrusive approach
- Consider using Maestro's proxy mode instead (requires app configuration)
- Disable VPN detection in debug builds if possible

## Advanced Usage

### Programmatic Access to Network Data

Network session data is stored in JSON format at:
```
~/.maestro/network-sessions/<flow-name>-<timestamp>.json
```

You can parse this file to:
- Build custom reports
- Integrate with monitoring systems
- Perform automated analysis
- Generate alerts on specific patterns

### Custom Certificate Authority

Use your own CA certificate:

```bash
maestro set-ca-cert --cert=/path/to/ca.crt --key=/path/to/ca.key
```

### Network Simulation

Combine with Maestro's network conditioning:

```yaml
# In your flow file
- startNetworkMonitoring
- setNetworkConditions:
    latency: 100ms
    bandwidth: 1mbps
- launchApp
- # ... your test steps
- stopNetworkMonitoring
```

## Known Limitations

1. **Certificate Pinning**: Apps with certificate pinning cannot have HTTPS traffic decrypted
2. **VPN Detection**: Some apps may detect VPN and alter behavior
3. **WebSocket**: WebSocket support is experimental
4. **HTTP/3**: QUIC/HTTP/3 is not yet supported
5. **Real Devices**: iOS real devices require manual VPN approval on first use
6. **Performance**: ~10% overhead on average, varies by traffic volume
